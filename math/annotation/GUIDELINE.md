# 人工标注规范（RQ1 / batch 2 评分器检验）

所有待标注的回答都被**原判分器判为错误**。你要判断的是：这个回答**为什么**被判错。

推荐用网页标注：用浏览器打开 `annotate_<名字>.html`（由 `make_annotation_html.py` 生成，需要联网显示公式）。每道题会显示题目、标准答案、程序抽出的答案、第一段代码之前的内容和回答结尾，所有 `\boxed{}` 都用黄底加框标出，可以展开完整回答。在网页上点选标签、写 notes，标完点 Download labels，交回 `labels_<名字>.csv`。标注只保存在当前浏览器里，换电脑或浏览器前先下载备份。

batch 1 的网页上有“脚本建议”（prelabel），仅供参考。**batch 2 没有脚本建议**，也不告诉你评分器怎么判，因为 batch 2 是用来独立检验新评分器的，标注时不要去猜评分器的结果。

## 四个标签

| 标签 | 含义 | 判断要点 |
|---|---|---|
| **A** | 答案写对了，只是没被抽出来（判分器误判） | 回答里**明确写出了**和标准答案等价的最终答案（例如 “x = 6”、“the domain is (2,12)∪(12,102)”），但没有放进 `\boxed{}`，或者框里的东西不是它的最终结论 |
| **B** | 没写出最终答案（且没有陷入重复） | 回答里**没有**出现最终答案：把计算交给代码（写完代码就停、说 “Let's run the code”），或者停在最后一步没算出结果。**不管方法和代码看起来对不对，都标 B**；方法明显正确的，在 `notes` 里写 “method correct” |
| **C** | 真的错了，或陷入重复 | 写出了一个**错误的**最终答案（不论有没有框、不论是正文写的还是自己编造的代码输出），或者**陷入重复循环**（即使前面写过正确答案也算），或者跑题 |
| **D** | 框了答案，答案其实对，判分器没认出来 | **只用于框了答案的回答**：`\boxed{}` 里的答案和标准答案**数学上等价**，只是写法不同（见下方“等价的写法”） |

## 判断顺序
1. 回答是不是**陷入了重复循环**（一直重复同一句话、同一个方程，或无休止地枚举）？是就标 **C**，notes 写 `repetition`。**即使循环前已经写出了正确答案，也标 C。**
2. 回答里有没有**明确写出最终答案**？正文结论、`\boxed{}`、模型**自己编造的** ` ```output ` 结果都算“写出了答案”。都没有就标 **B**（代码本身对不对不影响）。
3. 这个答案**对不对**（写法不同但数学上相等也算对）？不对就标 **C**。
4. 答案是对的：**没框**的标 **A**，**框了**的标 **D**。

## 团队讨论后确定的规则（batch 1 讨论结果）
1. **以最终答案为准。** 中间算对、最后改错了，标 C；最后写出的答案对，即使中间有小错，按答案标 A 或 D。
2. **写了多个答案时，看最后一个明确的结论。** 前后矛盾、看不出最终选了哪个，标 C，`notes` 写 `ambiguous`。
3. **模型编造的代码输出算作它给出的答案。** 写完代码后自己写了 ` ```output ` 结果：编造的结果错，标 **C**（不管代码本身对不对）；编造的结果对，按有没有框标 A 或 D。
4. **正确的框后面又出现空框，标 D。** 例如先写 `\boxed{15}`，再把题目指令抄一遍 “put your final answer within `\boxed{}`”。判分器取最后一个框（空的），所以判错。
5. **正文结论正确、但框里写了别的值，标 A。** 例如正文算出 1/4，最后却框了 5/8。（团队决定：以正文明确写出的结论为准；`notes` 写清楚。）
6. **等价要严格。** 题目要求的形式也算在内：要求“最简分数”却给了小数，要求区间却只给了端点，都不算等价，标 C。拿不准写在 `notes` 里，大家讨论。
7. **不要自己去解题。** 只判断回答里写了什么。需要时可以看标准解法确认等价。

## 等价的写法（框了的标 D，没框的标 A）
- 进制题省略或改写下标：标准答案 `52_8`，回答 `52` 或 `52₈`
- unicode 符号：`12π` 和 `12\pi`，`40₉` 和 `40_9`
- 加了格式命令：`\textbf{(B)}` 和 `(B)`
- 写成等式、右边正确：`5 × 6 × 8 = 240`，`\frac{...}{...} = 8n^2+4n+1`
- 无序的多个解换了顺序：`-2, 1` 和 `1, -2`
- 常见等价：`0.5` 和 `\frac{1}{2}`，`90^\circ` 和 `90`，多了单位

## notes 的写法
- `repetition`：陷入重复循环（标 C）
- `method correct`：方法正确，只是没得出或没写出最终答案
- `stopped before final step`：停在最后一步，没算出结果（标 B）
- `ends abruptly`：话说到一半突然停住，可能是被停止词截断（标 B）
- `ambiguous`：写了多个答案，看不出最终选哪个（标 C）
- `fabricated output`：自己编造了代码运行结果

## batch 2 新增：code_ok（只对显示了“代码实际运行的输出”的题）

batch 2 里，凡是回答中有 Python 代码的，网页会多显示一块“**代码实际运行的输出**”：这是**我们**替模型运行代码得到的真实输出（取打印的最后一行），不是模型自己写的。请另外回答一个问题：

| code_ok | 含义 |
|---|---|
| **Y** | 代码确实在计算**题目问的那个量**，并且这个真实输出就是正确答案（与标准答案等价，写法可以不同，如 `13/15`、`0.8666…`、`6.0*sqrt(2)`） |
| **N** | 其他所有情况：输出错误、运行失败或超时；输出只是一个中间量碰巧等于答案；输出把答案和其他数混在一起看不出哪个是答案；代码只是把正文里已有的数字原样打印出来 |

注意：
- **主标签（A/B/C/D）不受代码运行输出影响**，仍然只按“回答里写了什么”来判，和 batch 1 完全一致。例如：没写最终答案、代码运行输出正确 → 标签 **B**，code_ok **Y**；编造的输出错误、真实输出正确 → 标签 **C**，code_ok **Y**。
- code_ok 用来检验“把代码真实输出当作答案”是否可靠（报告里的 tool / code_any 两种口径）。

## 流程
1. **先标共享的题**（网页上标着“三人共同标注”，表格里 `assignee` 是 `ALL`；batch 1 有 20 个，batch 2 有 15 个），三个人各自独立标，不要商量。
2. 一起对比共享题的结果，讨论分歧，必要时修改本规范。**原始标注不要改**，分歧和讨论结果另外记录（报告里要报告讨论前的一致率）。
3. 再各自标自己的部分（`assignee` 是自己名字的行）。
4. 标完点 Download labels，把 CSV 交回，由脚本汇总。
