# 人工标注规范（RQ1）

所有待标注的回答都被**原判分器判为错误**。你要判断的是：这个回答**为什么**被判错。

推荐用网页标注：用浏览器打开 `annotate_<名字>.html`（由 `make_annotation_html.py` 生成，需要联网显示公式）。每道题会显示题目、标准答案、程序抽出的答案、第一段代码之前的内容和回答结尾，所有 `\boxed{}` 都用黄底加框标出，可以展开完整回答。在网页上点选标签、写 notes，标完点 Download labels，交回 `labels_<名字>.csv`。标注只保存在当前浏览器里，换电脑或浏览器前先下载备份。

“脚本建议”（`prelabel`）是按简单规则给的**建议**，只用来节省时间，可能是错的。每一道都要自己判断。

## 四个标签

| 标签 | 含义 | 判断要点 |
|---|---|---|
| **A** | 答案写对了，只是没被抽出来（判分器误判） | 回答里**明确写出了**和标准答案等价的最终答案（例如 “x = 6”、“the domain is (2,12)∪(12,102)”），但没有放进 `\boxed{}`，程序抽到了别的数字 |
| **B** | 没写出最终答案（且没有陷入重复） | 回答里**没有**出现最终答案：把计算交给代码（写完代码就停、说 “Let's run the code”），或者停在最后一步没算出结果。**不管方法看起来对不对，都标 B**；方法明显正确的，在 `notes` 里写 “method correct” |
| **C** | 真的错了，或陷入重复 | 写出了一个**错误的**最终答案（不论有没有框），或者推理出错、**陷入重复循环**（一直重复同一句话或同一个方程，即使没给答案）、跑题、自己编造了代码运行结果 |
| **D** | 框了答案，答案其实对，判分器没认出来 | **只用于框了答案的回答**：`\boxed{}` 里的答案和标准答案**数学上等价**，只是写法不同（例如 `0.5` 和 `\frac{1}{2}`、`90^\circ` 和 `90`、多了单位、顺序不同的集合） |

## 判断顺序
1. 回答是不是**陷入了重复循环**？是就标 **C**，notes 写 `repetition`；方法正确的再加 `method correct`。
2. 回答里有没有**明确写出最终答案**？没有就标 **B**。
3. 这个答案**对不对**（写法不同但数学上相等也算对）？不对就标 **C**。
4. 答案是对的：**没框**的标 **A**，**框了**的标 **D**。

## notes 的写法
- `repetition`：陷入重复循环（标 C）
- `method correct`：方法正确，只是没得出或没写出最终答案
- `stopped before final step`：停在最后一步，没算出结果（标 B）
- `ends abruptly`：话说到一半突然停住，可能是被停止词截断（标 B）
- `ambiguous`：写了多个答案，看不出最终选哪个（标 C）

## 规则
1. **以最终答案为准。** 中间算对、最后改错了，标 C；最后写出的答案对，即使中间有小错，按答案标 A 或 D。
2. **写了多个答案时，看最后一个明确的结论。** 如果前后矛盾、看不出最终选了哪个，标 C，并在 `notes` 里写 “ambiguous”。
3. **等价要严格。** 题目要求的形式也算在内：要求“最简分数”却给了小数，要求区间却只给了端点，都不算等价，标 C。拿不准时写在 `notes` 里，大家讨论。
4. **代码输出不算答案。** 回答里如果有模型自己编造的 ` ```output ` 结果，不当作最终答案（我们的评测没有运行代码）。如果正文另外明确写出了正确答案，仍然标 A。
5. **不要运行代码，也不要自己去解题。** 只判断回答里写了什么。需要时可以看标准解法来确认等价。

## 流程
1. **先标共享的 20 个**（网页上标着“三人共同标注”，表格里 `assignee` 是 `ALL`），三个人各自独立标，不要商量。
2. 一起对比这 20 个的结果，讨论分歧，必要时修改本规范。分歧本身要记录下来，报告里要报告一致率。
3. 再各自标自己的部分（`assignee` 是自己名字的行）。
4. 标完点 Download labels，把 CSV 交回，由脚本汇总比例和置信区间。
